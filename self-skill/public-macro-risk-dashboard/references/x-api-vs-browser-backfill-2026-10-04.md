# X 回填: API vs 浏览器实测对照 (2026-10-04, Chao 项目 Eco-and-Volatility-Checker)

## 结论
- 浏览器按天抓取(x_days.py)对高产账号**系统性漏帖**, 不能当完整回填: Gromen 漏9条(3.4%)+22条长推文被截断; Gundlach 漏13/58(22%, 多为同分钟连发串帖与UTC日界); Hunter(稀疏)0漏。
- API(search/all, 每条$0.005, 分页边界重复约1条/页)完整; 长推文必须取 note_tweet.text, text 会截断; text 里 & 被转义成 &amp;; 仅链接/媒体帖 text 为空(引用转推无评论单列 quote_only, 不静默丢)。
- counts/all 不可靠(对 -is:reply/-is:retweet 过滤无效, 低估2~3倍), 不能用来预估费用。
- 用量接口 /2/usage/tweets 返回 project_id 与 project_usage, 可确认 token 属于哪个项目, 但有延迟且看不到余额。
- 余额按开发者账号/项目独立; 注册赠送$20只给了第一个(同机多账号疑似只送一次, 文档未写, 未证实)。

## 必备门禁(都已在 tools/x_backfill/ 写成代码)
- xapi.py: 每次请求前按官方价预估, 超 HARD_CAP 抛错; 每页立即落盘 x_posts_store.json(崩溃不丢已付内容, 曾因内存丢失重付$1.5); per_query_cap 熔断(写了要实测会拦, 别把「写了」当「有效」)。
- 译文增量复用: 旧译文对新原文只查数字/标签查不出「原文被截断后变长」, 必须记录 src 并要求新旧原文逐字一致才复用; 另加「夹带英文原句」门禁。
- 账号核对: 门禁(姓名双命中+强机构词)会放行同名路人(牧师冒充 Adam Hamilton, 法学生冒充 James Grant, NYT作家冒充瑞士银行家); 上线扫描前必须按「简介无任何金融词」与名册身份逐个人工复核。
- 扫描脚本: 稀疏账号用 last_scan 时间避免每天重读2天窗口; 不要每天付$0.05做探针, 改为「扫>=20人全0条才报通道可疑」。

## 费用估算(Opus 5.5 评审, 外推自4人样本, 误差大)
198人×6月回填一次性中档≈$280(区间$100~780), 日更≈$44/月(198人)或$27(81人); 样本中位≈136条/人/3月, 范围15~261。

## 踩坑
- pkill -f 按脚本名会杀掉自己的终端(exit -15), 用 pgrep 看清再按PID杀。
- 通知写 completed normally 仍须看 EXIT 码; 「抓到0条」先用API已知有帖的日期当对照组。
