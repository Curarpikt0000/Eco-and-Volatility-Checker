# 侧栏菜单顺序必须 == 页面 DOM 顺序（Eco 看板「跳动感」根因，2026-10-06）

用户反馈「看 dashboard 还是有跳动感」。根因不是 scrollspy 判定线，而是菜单按关键词把相距几十屏的板块合并成同一组，而 scrollspy 用 DOM 序号 → 菜单自上而下读时页面位置倒退（3 处，高亮往回跳）。通用 scrollspy 技术见 skill `html-dashboard-sidebar-scrollspy`（用户自有，本条不能写进去，需 `hermes curator adopt` 后才能补）。

## 先量化，别凭感觉
用无头 Chromium 打开构建产物，注入探针（load 后 2.5s 写 `<pre id=PROBE>` JSON：顶级板块 `{id,t,y}` + 菜单 `{g,href,t}`），`--dump-dom --virtual-time-budget=12000` 取回（页面 15MB，预算要足）。判据三项：
1. 菜单 id 序列 == DOM 顺序（应为 True）；
2. 菜单自上而下读，页面 y 倒退次数（应为 0）；
3. 各组 y 跨度（极大=被硬塞）。
空集合陷阱：初测「菜单项 0 / 顺序一致 True」是空集合假阳性，断言前先打印两边数量。不要再靠用户开着的页面（CDP 隧道常断）——本地无头浏览器即可复现。

## 修法（根治，不是补关键词）
- 不再 `bucket[group].push`。收集阶段按 DOM 顺序记录 `{a, idx, hint}`。
- 无关键词命中的 section 并入相邻段；夹在同一组两侧的孤立离群项并入两侧。
- 渲染按 DOM 顺序切 **run**：连续同组=一个标题；同组被别组隔开=两段，第二段标题加「（续）」。
- pinLast（固定放最后）在页面里不在末尾时**不能改菜单顺序**，否则又与页面脱节。
- 新增板块无论关键词命不命中都不再错位；代价是分组标题变多（本次 15 个），要告诉用户，并把原「其他」里的板块按主题开新组。
- 关键词在更靠前的组会抢先命中（`'货币供应'` 同时命中「三国货币供应」和「全球货币供应与放水加速度」）→ 改用更长的限定词。

## 不整站构建也能验
把 `dashboard.py` 里新菜单脚本段（f-string 的 `{{ }}`→`{ }`）切下来，替换到现有 `docs/index.html` 同一段，再注入探针跑无头浏览器。验证后删掉已无调用的旧函数。验证脚本别把「删死代码」这种一次性步骤包进去（重跑会 `substring not found`，并让你误用旧产物当新结果）。

## 复盘
8-25 的旧修复只处理「图内小标题掉进其他」，没用全部板块的真实 y 坐标验证单调递增。凡声称「菜单与页面一致」，必须有 y 单调的实测数字。
