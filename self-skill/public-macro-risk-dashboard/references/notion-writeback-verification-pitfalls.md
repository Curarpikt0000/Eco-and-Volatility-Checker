# Notion 写后读回校验的隐形失效

## 事故：`ok=367 fail=0` 紧接着 `读回 2026-07 = None`

2026-09-21，全球 M2 回填。两句话互相矛盾，必须查清是哪边错。

**先拉原始返回体**（不猜）：2026-07 那行存在，数值全对 —— 合计 108.763 / 同比 8.97 /
加速度 1.8 / 五国分项齐全。**写入是成功的，坏的是校验工具。**

## 根因：`read_back` 与 `upsert` 参数不对称

```python
def read_back(db_id, title_value, field):   # ← 没有 title_field
    pid = query_by_title(db_id, title_value) # ← 吃默认值 "Date"
```

该 DB 的 title 字段叫 `Month`，过滤条件 `property="Date"` 永远查不到行 → 恒返回 None。
`upsert()` 一直有 `title_field` 参数（所以写入正常），**是 read_back 漏了**。

## 为什么这个 bug 特别阴险

它不会把失败误报成成功，而是**把成功误报成失败** —— 看起来「更安全」。
真正的风险：一旦有人（包括自己）认定「这张表读回 None 是正常的」而忽略它，
**这张表的写后读回校验就永久空转了**，真正的写入失败再也发现不了。
项目纪律里的「幂等 upsert + 写后读回」，在所有 title 字段非 `Date` 的表上一直是摆设。

## 修法 + 反测四条路径

给 `read_back` 加 `title_field="Date"` 并透传；扫全项目调用点补齐漏传的。

```
① 正常                     → 108.763  ✅
② 不存在的月份 1900-01      → None     ✅ 证明它不是恒真
③ 不存在的字段名            → None     ✅
④ 故意传错 title_field=Date → None     ✅ 复现 bug 本身
```
