# KOL 回填门禁入库 + 日报「当日精彩言论」新鲜度筛选（2026-09-29）

## 1. 日报 KOL 精彩言论：按「出处日期」筛，不按快照日期
- 每日全量抓取会给名册每个人都写一条，但多数人当天**没有新发言**，子 agent 会把几周前的旧文章再总结一遍。直接列出来就是把旧话当新话。
- 工具 `tools/kol_highlights.py`，纯机械判定，不调 LLM：
  - 从 kol_store 取 date>=since 的观点，同一人同一句 comments 去重；
  - 「新」= sources 里最新的**完整日期**（YYYY-MM-DD）>= since。只有月份（2026-09）的不收；晚于今天的丢弃并报数；
  - detail_status=none 或方向「未找到」的不收；同一人最多 N 条（默认 2）。
- 实测：窗口 9/21–9/29，名册 153 人，唯一观点 457 条，其中只有 **90 条 / 66 人**是真正新发表的。单日窗口常常只有约 10 人。
- 日报 prompt 规则：窗口内**全部**写上（Chao 要「所有精彩言论」）；段首写「N 人 / M 条（名册 X 人，其余无新公开言论）」；0 条时写「无新公开言论」，**不许用旧观点凑数**；观点冲突只陈述谁说了什么，不替他们下结论。
- 临时「上周到今天汇总」用同一个脚本加 `--since`，再按主题（黄金/美股/利率/原油/其他）组织；结尾点出多位 KOL 各自提到的同一个关键位（如 10Y 5.3–5.5%）。
- 显示层坑：Telegram 输出里 KOL 名字可能被脱敏器替换成 ANONYMIZED_PERSON_x，库里数据没问题，不要据此去改数据。

## 2. 一年期回填：子 agent 产出 → 机械门禁 → 入库
工具 `tools/kol_bf_ingest.py <batch_dir> [--apply]`，读 `<batch_dir>/out/<kol_id>.json`（裸数组）。
- G1 字段：date 必须是完整 YYYY-MM-DD；comments 非空；source 必须是 http(s)。
- G2 窗口：WIN_START <= date <= 今天。
- G3 方向：归一到 看涨/看跌/中性，其他值拒收。
- G4 **出处实测**（12 线程并发，109 条约 7 秒）：
  - 404/410/DNS 失败 → 拒收；
  - 200 但页面里没有本人姓氏 → 拒收（防张冠李戴/编造）；
  - 403/429/超时/JS 壳页面（<3000 字节）→ 保留，但计入「无法自动核验」单列汇报。
- G5 同人同日同 comments 去重。
- **入库时 kol_name 必须用名册 display_name**，kol_id 沿用该人在 store 里已有的 id（daily 行用的是短 slug，比如 `art_berman`，而名册 id 很长）。看板历史按 display_name 关联，写成短名会出现「入库了但看板不显示」。
- **先用对照组验证门禁会拒收**：造 6 条坏记录（404、真页面但没有本人、DNS 失败、窗口外、方向非法、日期不全）加 1 条真记录，应该拒 6 留 1。通过后才能用到真实批次。
- 入库前备份 `kol_store.sqlite`；汇报 inserted 和 updated 要分开写（重跑时已有的会记成 updated，不是新增）。

## 3. 缺月清单与编排
- 缺口口径：过去 12 个整月，每人 have_months / missing_months；缺 ≥3 个月的列入。9/29 实测 163 人中有 120 人。只看「有没有这个人」会严重低估，一定要按月份算。
- 规格文件每人给 missing_months，要求**只补缺失的月份**。
- 编排器 `scratch/kol_bf_gap110/orchestrate.sh` 的模式：
  - flock 单实例；
  - 先等上一批进程（`pgrep -f <前批>/run_batch.sh`）结束，免得同时十几个 `hermes -z` 抢额度；
  - 每轮 5 个进程，每个 2 人；每轮结束立刻 `kol_bf_ingest --apply`，把汇总写进 progress.log；
  - 断点续跑：已有 out 文件的人跳过；连续两次没产出的人写 `[]` 放弃，并在汇报里列出。
- 从 Hermes 终端启动时：前台命令里不能用 `&`。用 `terminal(background=true, notify=true)` 包住一个内部 `cmd & ... wait` 的循环。
- 以前中断的批次（例如 9/25 `kol_bf_full` 只完成 9/90）要先检查产物有没有入库，没入库就先过门禁再入库，再从新批次的 todo 里把这些人划掉。

## 4. 附带做法：通知型 no_agent 脚本改成静默
- Chao 讨厌刷屏：成功时一律不输出，只把数字追加到本地日志；失败、解析失败、有错误照常输出。
- 数据文件由自己的 cron 产出的，就由这个 cron 自己用 pathspec 限定目录来提交（`git commit -- data/xxx/`），push 后核对 local==@{u}。
  - 不要指望日报的 90 分钟 mtime 窗口能顺带提交它：13:30 的产物永远落不进 11:00 的窗口，何况那个脚本还把这批文件误排除成了「别人的」。
- 在临时 bare repo 里测 5 条路径：成功有改动、成功无改动、有错误、ingest 失败、push 失败。注意 `git push -q` 在 bare remote 下仍会把「remote: …」提示打到 stderr，要收进变量，失败时才打印，否则成功时也会发消息。
