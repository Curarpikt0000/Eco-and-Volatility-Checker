## 1. 网页(Chrome 隧道 localhost:9333, 按天搜索 from:X since/until -filter:replies)对 API 的漏抓率(实测)
- 稀疏账号(Hunter ~5条/月): 0%, 14 条
- Gromen: 3.4% + 22 条长帖被截断, 261 条
- Gundlach: 22%, 58 条
- 8 个高产号(Stockman/KingKong/FreightAlley…): 24%(各 12.5%~33%) + 大量截断, 771 条

- 我先后猜的两个根因都被证伪: ①「同日连发折叠」——当日只发 1 条的帖也漏 23%, 与当日 13+ 条(30%)无明显关系; ②「UTC/东京日界」——漏抓分布全天。长帖/引用转推占比也与抓到的相同。**根因未明**, 疑 X 搜索索引本身不全。别再把「连发折叠」当结论写。
- 结论: 网页只适合低产账号回填 / 粗扫 / API 没钱时兜底, 必须标 source=web 约漏四分之一; 不能满足「每条都要」。
- 可复用判别法: 先用 API 对 1~2 个账号拉同窗口全量当真值, 逐 id 求 仅API/仅网页/共有, 按「当日条数/UTC小时/长帖/引用」分桶看规律, 不凭直觉归因。

## 2. 网页抓取统计陷阱
since:D until:D+1 与帖子 UTC 时间错位, 同一 id 出现在相邻 2 个日文件。日志里「补抓 N 天 M 条」是重复计数(≈真实 1.85 倍); 汇总必须按 post id 去重。

## 3. 对照组纪律
抓到 0 条先别写「没发帖」: 拿必有帖的对照账号走同一通道, 通了 0 才可信。andrewmaguire1: 网页 36 天 0 条, 打开主页最新帖 2025-12-06 → 真无原创帖。users/by 的 tweet_count 只能证明账号真实, 不能证明近期有帖。

## 4. 每日扫描 cron(x_daily_scan.py, no_agent, 工作日 09:30 JST)的坑
- since_id 必须在 7 天内, 否则 X 返回 HTTP 400。稀疏账号游标帖龄常 >7 天 → 当天静默失败(曾 6/42 失败却显示「36/42」)。修法: 雪花 ID 解帖龄 (id>>22)+1288834974657 ms, >=6 天改 start_time=上次扫描时间。
- 单账号失败不得被吞: 熔断只管「连续 3 次」会漏掉分散失败; 输出必须单列「N 个账号没扫成」。
- 对照探测(search/recent 最小 10 条=$0.05/天)不划算, 可改「整轮扫≥20人全 0 条才报通道可疑」。
- 账本 HARD_CAP 要与真实余额对齐, 否则日更被旧 $8 上限误报「余额耗尽」。
- API 用尽(402)/超预算 → 剩余账号写 x_web_fallback_queue.json(按账号记缺口起止), 游标不动; 回「继续」才跑网页(占 Chrome/隧道, 不能无人值守)。
- 分页边界每页重复 1 条; counts/all 对 -is:reply/-is:retweet 无效, 不可用于估价; 估价用「前 10 条时间跨度外推窗口总数」, 超阈值标 high_volume 不烧钱。

## 5. 成本修正
帐号月帖量样本很偏(周末/周一单日实测与月均差 5~8 倍)。42 账号日更实测约 $10/月(区间 $6~18), 不是早先 Gromen 外推的 $19~44。回填半年 198 人 $280 中档估算仍未校准。

## 6. 工程小坑
- cdp_probe.py 曾只放 /tmp, 网关重启即丢, x_day.py 报 ModuleNotFoundError → 已存入 tools/x_backfill/。依赖放项目目录, 别放 /tmp。
- 后台脚本被 kill 后遗留的 x_day.py 子进程要按 PID 单独杀(pgrep -af 看清再 kill, 不用 pkill -f)。
- 链式长命令易被解析器 hardline 拦, 拆短命令; write_file 必带 path。
- 隧道反复断(三次), 重建只能 Chao 在 Mac 上做; 每轮开跑前 curl 验证 http 200, 断了熔断自动停。
