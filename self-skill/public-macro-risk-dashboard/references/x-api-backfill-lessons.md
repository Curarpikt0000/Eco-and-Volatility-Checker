# X API 回填 · 实测经验(2026-10-04, Eco-and-Volatility-Checker)

## 计费与接口(官方文档 docs.x.com + 实测)
- 按量计费: 读帖 $0.005/条, 读用户 $0.01/个, 同一资源同一 UTC 日内去重。
- 余额挂在「开发者账号/项目」: 用 `GET /2/usage/tweets` 可返回该 token 所属 project_id 与用量(看不到余额数字)。
  401=token 已失效(被再生成/应用删除), 402 credits-depleted=token 有效但项目余额为 0。
- 用量接口有延迟(读 1 条后立刻查仍不变), 不能当实时账本; 本地自建账本 + 每次请求前预估熔断。
- search/all(全历史, 500/页, 1 次/秒)对按量账号可用; `counts/all` 对 -is:reply/-is:retweet 过滤无效, 低估 2~3 倍, 不能用来预估费用。
- 分页边界会重复返回 1 条(每页多付约 $0.005), 按 id 去重即可, 不值得折腾。
- 长推文 `text` 被截断, 取 `note_tweet.text`; `text` 里 & 会变 &amp; (html.unescape); 纯图/纯链接帖 text 为空; 引用转推且无评论也为空 → 单列保留, 不静默丢。
- 不请求 expansions(是否另收读用户费未实测)。
- Chao 的 $20 是 X 注册时赠送, 同一台电脑多账号只有一个项目有(反滥用规则未证实); 不要再为拿赠送额度开新账号。

## 代码结构(tools/x_backfill/xapi.py)
- 总额硬上限 + 每 query 熔断 + **每页立即落盘**(崩溃不丢已付内容; 曾因只存内存损失 $1.5)。
- 熔断只写了没测过就不算有效: 下次动大额前先用 $0.03 上限实测会真拦。

## 翻译复用门禁(栽过的坑)
- 只查「数字/标签/@保留」查不出「原文被截断后变长, 旧译文停在截断处」。必须记录译文对应的 src, 复用前要求新旧原文逐字相同。
- 再加「夹带英文原句」门禁(译文含原文连续 25 字符, 排除 @ 与数字串)。
- 改门禁后全量复核时, 要用「翻译时的真实输入」(clean() 后文本)重判, 用原始 text 会因 URL/数字格式大量误报(一次误报 148 条, 我还差点误删译文库)。

## 费用估算方法
- 单人 3 个月实测: Gromen 261 / Gundlach 59 / Hunter 15 / Dowd 213 条(相差 17 倍), 4 样本偏高产大号。
- 198 人×6 月: 一次性约 $100~780(中 $280), 日更约 $16~118/月(中 $44); 81 人口径约 $69~337。
- 先抽 10 个已核实账号各拉 1 个月(约 $2~3)校准人均帖量, 再决定范围。

## 日更 vs 回填的分工(Chao 2026-10-04 定)
- X 现金预算不足 → 日更走 API since_id(新帖才付费, 扫描与拉取是同一次调用, 再开网页是重复劳动)。
- 回填走浏览器分批(每天最多 3 人, 间隔 12 秒, 连续 3 次失败停); API 返回 text 为空的帖才开网页补读被引用内容。
- 我的 turn 只由消息驱动: 回填不能承诺「放着自己跑完」, 只有 cron 里的脚本部分能无人值守。
