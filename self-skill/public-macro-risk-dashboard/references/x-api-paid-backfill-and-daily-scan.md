# X API 按量计费: 账号核对 / 回填 / 每日扫描 (2026-10-04 实测)

只记「下次直接用得上」的事实与门禁。价格/限额以 docs.x.com/x-api/getting-started/pricing 当时为准。

## 计费与额度(官方文档原文 + 实测)
- 读帖 $0.005/条, 读用户 $0.01/个, 同一资源同一 UTC 日内去重。**请求次数不收钱, 只按返回条数**。
- 余额挂在**开发者账号/项目**, 不是 token。多个 token 可能属于不同项目: `GET /2/usage/tweets` 返回 `project_id`/`project_usage`, 用它判断「几个 token 是不是同一个项目」; 401=token 已被再生成作废, 402=有效但余额 0。
- Chao 的 $20 是注册赠送, 同机多账号只有一个拿到(推断, 官方文档没写); 其余项目余额 0, 不要为拿赠送再开新号。
- `/2/usage/tweets` 用量计数**不是实时**(刚读完 1 条仍显示不变), 不能当作逐次扣费的证据。
- 官方文档没写「余额按账号还是项目算」: 答不出就说文档没写, 别补。

## 接口实测
- `search/all`(全历史, 1 次/秒)对该账号开放; 回溯 6 个月可行。`users/:id/tweets` 一页 100 条约一个月。
- **`counts/all` 不可靠**: 对 `-is:reply/-is:retweet` 过滤无效(4 种查询返回同一个数), 低估 2~3 倍(Gundlach 19 vs 实际 59, Dowd 73 vs 213)。不能用来预估花费。
- **长推文**: `text` 会截断, 必须取 `note_tweet.text`(Gromen 495 字 vs text 307 字)。`text` 里 `&` 是 `&amp;`, 要 `html.unescape`。
- **分页边界会重复返回 1 条**, 按 id 去重; 账本按返回条数记账更接近真实扣费。
- 仅链接/媒体/引用无评论的帖子 `text` 为空: 单列 `quote_only`, 保留链接+被引用 id, **不要静默丢**(旧网页版靠卡片文字有正文)。
- 不请求 `expansions`(是否另收读用户费未实测)。

## 帖量差异大, 成本不能用单样本外推
- 3 个月原创+引用: Gromen 261 / Dowd 213 / Gundlach 59 / Hunter 15(唯一)。中位约 136, 相差 17 倍。
- 198 人×6 月回填: 中档约 $280(区间 $100~780), 每日增量约 $19~44/月。最大不确定来源=人均帖量与「真有活跃账号的人数」。先抽 10 个已核实账号各拉 1 个月($2~3)校准再决定范围。
- 查询层预过滤几乎省不了钱: `-lang:und` 会误删 2 条真言论; 关键词排除「感谢/上节目」理论最多省 $0.06 且误删 10 条。引用转推约占 52%, 但 Chao 定了「引用转推保留」, 不要用 `-is:quote`。

## 封装必须自带的硬门禁(靠代码, 不靠记得)
- 每次请求前按官方价预估, 累计超 HARD_CAP 抛 `BudgetExceeded`; 402 同样视为余额耗尽。
- **每页立即落盘**(`x_posts_store.json`, post_id 去重): 崩溃时内存里已付费的内容不会丢(栽过: 3 人 $1.5 付了没存)。
- per-query 熔断(承诺过「每人 $4」就必须真写进代码, 并用 $0.03 之类小上限实测一次它真会拦)。
- 预估按「页大小×单价」算(别按 500 条/页预估, 否则被总上限误拦)。
- 账本只记我方调用, 看不到 X 后台真实余额; 真实耗尽以 402 为准, 账本做 80% 预警。

## 账号核对(users/by 批量, $0.01/个)
- 网页「人物搜索」对约 37% 的名册失灵(返回热门推荐: 特朗普/BBC 等), 对照组 Gromen/Dalio 也搜不到 → 搜索失灵≠账号不存在。
- 门禁(机械): 显示名姓+名双命中 + 强机构词(剔除姓名本身、剔除 capital/research/group 等通用词, ≥2 个或 1 个且≥6 字母) 或 认证且粉丝≥1 万 + 非备份/模仿/粉丝/诗歌节等 BAD 词 + 账号≥1 年。
- **这套门禁仍会放行同名路人**: 事后逐个查名册身份, 8/50 个 verified 其实是路人(James Grant→NC 法学生, Adam Hamilton→牧师, Thompson→NYT 作家等)。额外抽验口径: 简介里无任何金融词的 verified、粉丝最少的 10 个; 判据没被证明能区分真假前不能当结论。
- 术数/灵媒/阴谋论/宗教类账号不属于 Eco, 扫描名单要显式排除(`x_scan_exclude.json`)。

## 每日扫描(no_agent cron)设计
- 每人一次 `from:<h> -is:reply -is:retweet` + `since_id` 游标; 无新帖=无费用; 稀疏账号另存 last-scan 时间做 start_time, 避免每天重读 2 天窗口重复付费。
- 每日硬上限 + 累计预警 + 402 告警; 成功静默, 有新帖一行汇总。
- **通道健康别用单独探测**(search 最小 10 条=$0.05/天≈$1.5/月)。改为「扫了 ≥20 人却全 0 条」才报通道可疑, 且不更新 last。「没新帖」不得等同「没抓到」。
- 回填 vs 日更分工: 回填(一次性大头)可用浏览器 $0 分批做; 日更直接 API(扫到的就是拉到的, 再开网页是重复劳动)。浏览器版对稀疏账号 14/14 与 API 一致, 对高产账号会漏/截断(Gromen 漏 9、截断 22), 需分别对照。

## 增量翻译复用门禁
- 只复用「译文所对应的原文 == 当前原文(去空白/URL 逐字相同)」的旧译文; 只查数字/标签的门禁查不出「原文被截断后变长」, 实测栽过。记录译文时必须存 `src`。
- 加「译文夹带英文原句连续 25 字符」门禁(抓出 proforma 整行原样抄入)。复核必须用**翻译时的真实输入**(clean 后文本), 用原始 API 文本会误报 148 条。

## 公开仓库红线
- 推文英文原文、账号简介属第三方内容: 公开仓库只放 id/日期/链接+中文译文; `x_posts_store.json`、`*_raw.json`、账号简介文件写进 `.gitignore`。已推送的旧提交里原文仍在, 清除需 force push(不可逆, 需 Chao 明说), 默认只新提交去掉。
- 提交前扫: 暂存区含原文连续 40 字片段的推文数必须为 0 + 密钥扫描。
- token 只写 `.env`(新变量名不覆盖旧的), 用环境变量传入脚本, 不回显; 聊天里贴出的 token 建议事后在 X 后台再生成。

## 操作坑
- `pkill -f <脚本名>` 会杀掉自己的终端(exit -15): 先 `pgrep -af` 看清, 用精确 PID。
- 后台任务通知写 "completed normally" 仍须看 EXIT 码(本次 EXIT=143 其实是被我杀的)。
- 用户无法查余额时: 用 `usage/tweets` 的 project_id 区分项目, 让用户去 console.x.com 看 Billing 数字, 不要猜「延迟/风控」。
