# 采集面 ≠ 报告面：报告型管道最容易长期失衡的地方

> 2026-08-24 实证（Eco-and-Volatility-Checker）。用户一句「你基本上考虑了所有的表格，
> 还是说只考虑了其中一部分？」一问即中 —— 答案是**只报了一部分**，而且已经漂了几个月。

## 结论先行

采集端随需求**不断追加板块**，报告端的措辞却是**当初一次性写死的**。
两者之间没有任何机制强制同步，于是「抓到但从不上报」的板块**单向累积**：
不报错、不告警、看板一切正常，只有用户主动质疑才会暴露。

实测规模：看板 **45 个 section**，cron 发报步骤只点名 **6 骨架 + 5 附加项**；
`external_data` 有 **42 个 fetcher、38 个被调用**。
→ 压力面板 / 拍卖 / 托管余额 / 信贷脉冲 / 交割榜全套 / 库存 / 广度 / 跨境支付 /
产业链财务 等 **30+ 板块，天天抓、天天进看板、从不进日报**。

## 诊断三步（可直接套用到任何 cron 报告型管道）

1. **数 section 总数 ← 报告实际点名的模块数**，差额就是盲区规模。
   `grep -o 'class="part-title"' 产物.html | wc -l` vs 通读发报 prompt 数模块。
2. **列 fetcher 全集 ← cron 调用集合**，差集里区分「已弃用」与「真遗漏」。
   ```python
   avail = {n for n in dir(external_data) if n.startswith('fetch_')}
   used  = set(re.findall(r'\b(fetch_[a-z0-9_]+)\s*\(', cron_prompt))
   sorted(avail - used)
   ```
3. 对每个「疑似没数据」的板块，**先读 fetcher 返回值再下结论**（见下节）。

## ★误诊教训：「某板块没出现在报告里」≠「没抓到数据」

本次我先断言「欧洲央行是空的，因为那个 fetcher 没被调用」——**错**。

真相：主 fetcher **本来就返回四家央行**，欧洲那份 6 个资产项一直都在，
看板早已渲染出总资产；**只是报告文案从头到尾写着「三大央行」**，把第四家漏在了措辞里。
另有一个同名独立 fetcher 属冗余，未被调用完全正常。

**判据顺序（固化）**：
```
① 跑 fetcher 看返回值  →  ② 看渲染产物是否有该板块  →  ③ 最后才怀疑采集层
```
跳过前两步直接归咎采集，会把**文案缺陷误诊成数据缺失**，修错地方。

## 结构性对策：固定模块骨架 + 占位 + 数据健康度

报告骨架改为**固定模块清单**（本项目为 12 模块：核心指标/结论动作/流动性/
四大央行/债务财政/利率与国债压力/信用/外国持有美债/贵金属/大宗其他/KOL与机构/
今日焦点+数据健康度）。三条规则：

- **有变动详写，无变动一行带过**。
- **低频板块当期无更新也要占位输出**「(季度/年度，本次无更新)」，而不是整块消失。
  占位的价值不在信息量，而在**让人一眼确认「所有板块都被看过了」**——
  模块消失和模块无变化，在读者眼里长得一样，含义却天差地别。
- **新增「数据健康度」节**：列当期未就绪/抓取失败/校验不符项，
  **全部正常时也必须写一行「全部数据源正常」**，否则某个源悄悄挂掉没人知道。

用户明确表态：**「不用在乎日报是不是太长，重要的是关键信息有没有包含全，
以及分层结构是否方便人类阅读清晰。」** → 篇幅不设上限，但必须分层。

## 改 cron prompt 的施工纪律

这类 prompt 里常内联着 `dashboard.generate(...)` 之类的长参数调用，改别处极易误伤。
**改完必须精确复核参数个数**（本项目基线 47 个）：

```python
i = prompt.find('dashboard.generate(')
depth = 0
for k, ch in enumerate(prompt[i:]):
    if ch == '(': depth += 1
    elif ch == ')':
        depth -= 1
        if depth == 0: body = prompt[i:i+k+1]; break
len(re.findall(r'(\w+)\s*=', body))
```

**不要用宽松正则**：说明文字里往往也出现同名函数字样，会切错片段得出
「参数丢了」的假警报（本项目已因此误判两次）。

## worked example：用户说「有个指标我们好像遗失掉了」

用户给出两个可核对的数字（本周成交额、某日某机构成交额）时，
**先用它们做交叉验证再谈接入** —— 数字对上才证明找对了源。

本次：央行美元流动性互换 → 纽约联储官方 API，免费无 key、可查历史。
- 端点：`markets.newyorkfed.org/api/fxs/all/search.json?startDate=&endDate=`
- **`/latest.json` 常返回空数组**（只在当日有新操作时才有值），不能用作主源。
- `amount` 单位是**美元原值**（非百万/十亿），除 1e8 得「亿美元」。
- 字段：`tradeDate / counterparty / amount / termInDays / interestRate / maturityDate`。
- 交叉验证通过后再写 fetcher、建板块、接 build 管线。
