# 实体档案卡 & 两层展开（2026-08-23 实战）

适用：dashboard 里「每个实体一张卡 / 点开看详情」的板块 —— KOL 名录、机构档案、
标的档案。本页记 Chao 明确要过的规格与两个真实 bug。

---

## Bug 1：两层展开必须有两层内容

**用户反馈**：「点开第二层，跟折叠时那一句话没有任何区别」。

**第一反应会以为是渲染 bug —— 不是。** 先量化数据层再改代码：

```python
c = [x['comments'] for x in data]
print('中位', sorted(map(len,c))[len(c)//2], '最长', max(map(len,c)),
      '≥100字', sum(1 for x in c if len(x)>=100),
      '有detail字段', sum(1 for x in data if x.get('detail')))
# → 中位 32 字 / 最长 51 / ≥100字 0 人 / detail 字段: 不存在
```

根因：**数据层只有一个文本字段**，前端折叠态和展开态复用同一个 `comments`，
所以两层永远一样。修法是补数据（每人 100-300 字四段式 `detail`），不是改渲染。

**教训**：用户说「点开没区别」时，先测数据层字段数与长度分布，别直接改 CSS/JS。

### 链路要打通到底

补了 `detail` 字段后仍然不显示 —— 因为 `kol_full_history()` 的**两条聚合路径都没
透传 detail**。改渲染层之前，先确认字段从「磁盘 → 聚合函数 → payload → 前端」
每一跳都带着。内嵌 payload 是数组形态时（省体积），新增字段要同时改
**打包端下标**和**前端解构注释**：

```python
# payload: [first, last, direction, comments, targets, source, detail, srcs]
#                                                          ^新增 ^新增
```

## 13 维度档案卡（Chao 2026-08-23 逐条指定，一个都不能少）

姓名 / 编号 / 领域 / **在世年份** / 现任头衔 / 代表性成就 / 荣誉 /
主要活动范围 / 观点 / 追踪价值 / 机构名称 / **书籍** / **代表性言论（仅当年）**

### 缺失口径（Chao 明确，必须照做）

| 情况 | 写法 |
|---|---|
| 年龄/生年查不到 | 「未公开」（Chao: "年龄查不到无所谓"）|
| **已故者** | **必须标「已故」+ `deceased=true` + 卡片红色徽章** |
| 机构合并条目（非自然人）| 在世年份写「机构条目（非自然人）」；书籍写「无公开著作（机构研究条目）」；荣誉注明不适用个人奖项 |
| 确认没写过书 | 「无公开著作」|
| 不确定是否写过书 | 「未检索到公开著作」（**和上一条要分开**）|
| 当年无公开言论 | 「20XX 年未检索到公开言论」；已故者补「（本人已于 XXXX 年逝世）」|

### 采集阶段两个真实高频坑

1. **第三方传记 ≠ 本人著作**。亚马逊/Goodreads 上「关于他的书」被多次误记为本人著作。
   prompt 里要写死这条，实测子 agent 能正确判为「无公开著作」。
2. **同名干扰**。实测 10+ 例：分析师 vs 同名古生物学家 / 小说家 / 足球运动员 /
   水彩画家 / 飞镖选手 / 童书作者。要求 **确认职业领域匹配再采用，不匹配就在字段里
   注明已排除同名者**。

### 副产品：名册 bio 会过时

联网核实 13 维度时顺带发现 **20+ 人头衔已变更**（卸任 / 跳槽 / 公司更名 / 转 Emeritus）。
档案按现状写，但**名册本身不要改** —— SSOT 在 Notion 侧，只做单向镜像。

## 渲染层规格

- **不写死人数**：直接读名册 `active` 全量生成，Notion 侧新增一位次日自动多一张卡。
- **按领域分色成组**：`domain` 去重后配莫兰迪同系色板，组标题条 + 卡片左边框同色。
- **无档案者显示「档案待补」**，只列名册已有字段，**绝不用模型猜写**；
  表头给 `档案 N/M` 完成度。
- 卡片放**页面最底部**（备查性质），不要插在分析板块中间。

### 验收计数的陷阱

`h.count('kp-todo')` 会把 **CSS 类定义** `.kp-todo {` 也算进去，导致"明明档案全了
却显示待补 1"。验收计数要用带引号的完整属性：`h.count('class="kp-todo"')`，
或先确认命中位置是不是 `<style>` 段内。
