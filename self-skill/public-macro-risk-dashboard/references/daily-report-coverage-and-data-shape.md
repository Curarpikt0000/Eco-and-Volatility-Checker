# 日报覆盖面、字段形状漂移、回填日期校验

三条彼此独立、都在 2026-08-23/24 实战中付出代价换来的教训。前两条是**报告类管道的通病**，
第三条是**回填类任务的红线**。

---

## 一、采集面 ≠ 报告面（用户主动质疑才暴露）

**用户原话**：「这些基础数据是如何取得的？你基本上考虑了所有的表格，还是说只考虑了其中一部分？」
一问即中 —— 答案是**只报了一部分**。

### 为什么会发生

采集端随需求不断加板块，**报告端的措辞是当初一次性写死的**。两者之间没有任何机制强制同步，
于是「抓到但从不上报」的板块**单向累积**：不报错、不告警、看板上一切正常。
只有用户主动怀疑才会暴露。

### 实测数字（本项目）

| 项 | 数量 |
|---|---|
| dashboard section | **45** |
| cron 发报步骤点名的模块 | 6 骨架 + 5 附加项 |
| `external_data` fetcher 总数 | **42** |
| cron 实际调用 | **38** |
| **抓了但从不进日报的板块** | **30+** |

盲区包括：压力四联图、国债拍卖、托管美债、信贷脉冲、COMEX 全套（库存/周净/top10/COT/
BIS掉期/黄金出口/亚洲溢价/白银进口）、石油库存、市场广度、日经外资、CIPS、AI 产业链、
IIP、百年收益率、再融资墙。

### 诊断三步（可套用到任何 cron 报告型管道）

1. 数看板 section 总数 ← 报告实际点名的模块数，差额 = 盲区规模
2. 列 fetcher 全集 ← cron 调用集合，差集里区分「已弃用」与「真遗漏」
3. 对每个「疑似没数据」的板块，**先读 fetcher 返回值再下结论**（见下节）

```python
# 数 fetcher 差集
import re, json
avail = sorted(n for n in dir(external_data) if n.startswith('fetch_'))
used  = set(re.findall(r'\b(fetch_[a-z0-9_]+)\s*\(', cron_prompt))
missing = sorted(set(avail) - used)
```

### ★误诊教训：「没出现在报告里」≠「没抓到数据」

我先断言「欧洲央行是空的，因为那个 fetcher 没被调用」—— **错**。
真相：主 fetcher `fetch_cb_balance_sheets()` **本来就返回四家央行**，欧洲那份 6 个资产项
一直都在、看板早已渲染出总资产；**只是报告文案从头到尾写着「三大央行」**，把第四家漏在了措辞里。
另有一个同名独立 fetcher 属冗余，未被调用完全正常。

**判据顺序（固化）**：
1. 先跑 fetcher 看返回值
2. 再看渲染产物（HTML/JSON）里有没有
3. 最后才怀疑采集层

跳过前两步直接归咎采集，会把「文案缺陷」误诊成「数据缺失」，修错地方。

## 二、用户对日报形态的明确要求（2026-08-23）

**原话**：「日报应该根据每天可以更新的所有 dashboard 数据来做，而不是只包含其中一部分。
日报可以分成不同的模块，比如流动性、债务、信用、贵金属等等。**不用在乎日报是不是太长**，
重要的是**关键信息有没有包含全**，以及**分层结构是否方便人类阅读清晰**。」

### 落地成固定 12 模块骨架

```
开头：一句话总览（综合信号 + 触发 X/7 + 今日焦点）
① 核心指标与警报      ② 综合结论与动作     ③ 流动性
④ 四大央行资负表      ⑤ 债务与财政         ⑥ 利率与国债市场压力
⑦ 信用                ⑧ 外国持有美债/去美元化
⑨ 贵金属              ⑩ 大宗与其他市场     ⑪ KOL 与机构行为
⑫ 今日焦点 + 数据健康度
```

### 三条设计规则（都不是可选项）

1. **有变动详写、无变动一行带过** —— 保证信息全但不啰嗦。
2. **低频板块无更新也要占位输出**「(季度/年度，本次无更新)」，而不是整块消失。
   占位的价值不在信息量，而在**让人一眼确认「所有板块都被看过了」**——
   模块消失和模块无变化，在读者眼里长得一样，含义却天差地别。
3. **末尾必须有「数据健康度」节**：列当期未就绪/抓取失败/校验不符项，
   **即使全部正常也要写一行「全部数据源正常」**。否则某个源悄悄挂掉没人知道。

篇幅不设上限，但**必须分层**（模块标题 → 缩进要点行 → 关键数字加粗），不要糊成一大段。

### 改 cron prompt 的施工纪律

这类 prompt 里常内联着 `dashboard.generate(...)` 之类的长参数调用（本项目 **47 个参数**），
改动别处极易误伤导致板块静默丢失。**改完必须精确复核参数个数**：

```python
# 正确：找到调用起点后按括号配对取出完整调用体，再数关键字
i = p.find('dashboard.generate(')
depth = 0
for k, ch in enumerate(p[i:]):
    if ch == '(': depth += 1
    elif ch == ')':
        depth -= 1
        if depth == 0: end = k; break
n = len(re.findall(r'(\w+)\s*=', p[i:i+end+1]))
```

**不要用宽松正则**：说明文字里往往也出现同名函数字样，会切错片段得出「参数丢了」的假警报
（本项目已因此误判两次）。

## 三、上游字段形状漂移：兜底放在消费端

**线上实崩**：`AttributeError: 'list' object has no attribute 'strip'`，每日 build 全挂。

**根因**：`targets` 字段由 LLM / 人工 / 历史脚本混合写入，绝大多数是字符串，
**7 条被子 agent 写成了数组** `["黄金$6000","白银$120","铜$7"]`。

### 比崩溃更危险的是不崩的那几处

同字段在取数层有 4 处做 `[:150]` 截断 —— **对数组切片完全不报错，会静默切成子列表**，
数据悄悄变形，日志一切正常。**崩溃反而是好事（立刻暴露），静默变形才是长期数据污染的来源。**

→ **排查时不能只修报错那一处**，要把该字段所有取用点全列出来一起加固
（本次共 7 处：渲染层 3 + 取数层 4）。

```bash
grep -n '\.get("<字段>")' src/*.py     # 先枚举全部取用点
```

### 处置原则：改消费端，不改上游数据

数组本身是合法表达（多个标的），回头压成字符串反而丢结构。
正确做法是写归一函数，所有取用点统一走它：

```python
def _tgs(v, limit=None):
    if v is None:                      s = ""
    elif isinstance(v, (list, tuple)): s = "、".join(str(x).strip() for x in v if str(x).strip())
    else:                              s = str(v).strip()
    return s[:limit] if limit else s
```

### ★踩坑：加辅助函数前先查重名

我给归一函数取的短名与文件里一个**已有的局部变量同名**，函数在运行时被那个变量覆盖，
后续调用报 `'str' object is not callable` —— 一个本来只是「加固」的改动反而制造了新崩溃点。

更讽刺的是，那个同名局部变量所在的代码段**本来就已经正确处理了数组**——
说明这个坑之前有人踩过并局部修过，但没有上升为全局约定。

**教训**：
- 短命名（`_tg`/`_x` 这类）在长文件里极易撞名，加函数前先 `grep -n '\b<名字>\b'`
- **发现某处已有针对性防御，说明这是系统性问题**，应就地推广为公共函数，而不是各修各的

## 四、跨日期回填必须做窗口硬校验（防伪造历史）

**曾犯的错**：回填脚本按「(KOL, 日期就近)」把摘要贴到历史条目上 ——
「日期最近的下一条」**可能是完全不同的另一条观点**。实测 **972 条错配**
（2025-12-18 的观点被贴上 2026-04-08 的摘要）。这是伪造。

**正确匹配键**：只按 **(实体, 内容全文)** 精确匹配。同一观点跨多天时内容字符串本就相同，
用内容当键天然覆盖区间，且不可能贴错。

**回填脚本四道关**：
1. **日期硬校验** —— 每条 date 必须落在该实体的 `window_from ~ window_to` 内，**越界一律拒收**
   （越界意味着把无日期内容随便标了个日期 = 伪造历史）
2. 同日同文去重
3. 不覆盖已有条目，只增量追加
4. 幂等，可重复运行

**父端必须独立复核，不信子 agent 自报**：

```python
oob = [(r['id'], rec['date']) for r in rows for rec in r['records']
       if not (win[r['id']][0] <= rec['date'] <= win[r['id']][1])]
assert not oob, oob      # 越界 / 无日期 / 无来源 三项都要复核
```

**只看「回填成功 N 条」的日志会以为超额完成** —— 本次正是内容一致性校验才发现 972 条错配
（1188 条输入却回填了 2160 条，数字虚高就是信号）。

**零条目要允许且要有理由**：已故者、同名干扰无法确认、缺口窗口仅 5-6 天期内无公开发声 ——
宁可 0 条也不凑数。子 agent prompt 里要写死这条。
