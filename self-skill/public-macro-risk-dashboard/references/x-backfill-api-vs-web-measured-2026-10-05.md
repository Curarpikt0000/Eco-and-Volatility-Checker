# X 回填: 官方 API vs 网页逐个打开 — 实测结论 (2026-10-05)

接 x-api-vs-browser-backfill-2026-10-04.md。本篇只放后来补测的对照数据与可复用的门禁/排障做法。

## 1. 网页(按天搜索 from:X since:D until:D+1)对 API 的漏抓率 — 实测
- Hunter(稀疏,约6天1条) 14 条: 漏 0%
- Gromen 261 条: 漏 3.4%, 另有 22 条长推被截断
- Gundlach 58 条: 漏 22%
- 8 个高产号(近1月) 771 条: 漏 24%(单账号 12%~33%), 另有大量文本被截断
结论: 稀疏账号网页基本够用; 高产号网页漏约四分之一, 只能标 source=web/约漏四分之一, 不得冒充完整。
**别猜根因**: 曾假设「同日连发折叠」「UTC 日界」「长推/引用转推」「按小时」, 分桶验证全不成立(当日只发1条的也漏23%, 与当日条数无关)。切 6 小时窗口、去 -filter:replies、换 f=top 均找不回漏掉的帖。根因仍未知, 别写进文档当事实。

## 2. 对照实验写法(可复用)
- 先用 API 把同账号同窗口拉全并每页落盘, 再逐账号逐条与网页集合求差: 仅API(网页漏)/仅网页/文本分类(一致/网页截断/仅空白标点/内容不同)。
- 比对前先按 created_at 对齐窗口; 网页日文件必须按帖子 id 去重再计数 — 同一帖会同时出现在相邻两个日文件, 脚本汇总的「N条」是重复计数(约 1.85 倍)。
- 对照口径有缺陷就不要报数: 例如 API 只拿「最新10条」去对网页「整月」, 算不出漏抓率。

## 3. 每日扫描 cron 的坑(真踩的)
- search/recent 的 since_id 必须在 7 天内, 否则 HTTP 400。稀疏账号游标帖龄常>7天 → 脚本把 400 当普通异常吞掉, 输出仍写「36/42 人 ok」。修法: 游标帖龄(雪花ID>>22 + 1288834974657 ms)>=6天改用 start_time=上次扫描时间; 任何账号失败必须在输出里明说「N 个账号没扫成」。
- 熔断/上限要实测会拦(设 $0 日上限强制触发, 验证队列写出+游标没动), 测完删掉测试写入的队列, 否则假缺口被当真。
- API 用尽/402/当日上限 → 没扫完账号写入 x_web_fallback_queue.json(记缺口起点); 网页脚本只补缺口(to 字段闭区间); 排序先跑「API 已知有帖」账号(可对照), 0 条账号最后。
- 0 条账号不要当「没发帖」: 打开账号主页看最新一条日期(andrewmaguire1 主页最新 2025-12-06 → 半年窗口确无原创帖, 才可出队)。
- 网页脚本依赖的 cdp_probe.py 曾只放 /tmp, 网关重启后丢失 → 必须放进项目 tools/ 目录。
- 隧道 localhost:9333 会反复断, 只有 Chao 能在 Mac 重建; 启动前 curl /json/version 验证; 熔断「连续3次失败停」按设计工作。
- 杀后台任务: 先 pgrep -af 看清, 按精确 PID kill; 父脚本被杀后 x_day.py 子进程会遗留, 要单独杀。

## 4. 账号核对残余风险
API 阶段一的 verified 里仍混有同名路人(Adam Hamilton=牧师, James Grant=法学生, pomeranian99=NYT 作家)。按「简介无任何金融词」筛一遍能抓出一类, 仍要逐个对名册身份人工过眼。

## 5. 缩范围的依据
按实测月帖量排序保留 20 个、移出 22 个(写 x_scan_exclude.json, 可逆)。单日实测不能代表月均(周一窗口约20小时, 估8.6条/天的账号实测1条), 成本只给区间。月成本实测量级约 $10(区间 $6~18), 不是早先按 Gromen 单样本外推的 $19~44。
