# 发布整站 / 加板块的四个坑 (Eco-and-Volatility-Checker, 2026-10-14 实测)

## 1. 隔离构建不能直接拿去发布
- /tmp 隔离副本 rsync 时排除了 `.env` → 读不到 Notion → 依赖 Notion 的板块(中国央行流动性/ETF 份额/两融)渲染成「未就绪」。拿它覆盖线上=板块退化。
- 隔离构建只用来**验证新板块**;发布一律用项目目录(带 .env)重建。
- 想要「读 Notion 但不写」:写包装脚本,在 `runpy.run_path(build_dashboard.py)` 之前把 `notion_writer._req` 与 `external_data._req`(它是 `from notion_writer import _req` 的副本,必须单独覆盖)换成守卫:放行 GET 与 `POST …/query`,其余返回 `(403, {})` 并记录。先用假 `_req` 自测守卫(读放行、PATCH/POST pages/DELETE/blocks 全拦),再跑真构建,结束时打印被拦清单当「没写 Notion」的证据。本项目每次会拦 2 个:国债压力、OFR 最新值写入(次日 cron 会补)。
- 发布前核对清单:旧页备份 → 板块标题集合对比(丢失=0)→「未就绪」计数不增 → playwright 零 pageerror → 菜单 id 序 == DOM 序 → 红线 grep → `publish_cf_pages.sh` → `publish_vibe.sh` → curl 线上页 sha 与本地一致。

## 2. 新板块的位置决定菜单分组
- 菜单按 **DOM 顺序**渲染,分组只是「相邻 section 的小标题」:同组被别组隔开会分成两段;标题关键词没命中任何组 → 并入前一段。
- 把新板块插进两个同组板块中间 = 把一组切断(铀板块第一次就插进了金银短线图与金银回调之间,菜单里被并进黄金白银组,重构建才发现)。先放进目标组**末尾**。
- 菜单 GROUPS 的 JS 对象在 f-string 里要写成 `{{ name: '铀', match: ['…'] }},`(双花括号),整行追加,别往已有行中间插;标题里必须含 match 关键词。

## 3. 克隆已有渲染函数做姊妹板块
- 「K 线+均线+RSI」板块(铀,克隆金银短线图):程序化克隆源函数文本,前缀 `gst-`→`urt-`、`.gst`→`.urt`,改文案/口径句;generate() 形参、传参、build_dashboard 接线、菜单四处缺一不可(项目有「形参门禁」会报漏传)。
- 没有免费日线的标的(铀现货 U3O8)用实物信托(SRUUF、YCA.L)作代理,页面注明「二级市场价、有溢价/折价、不等于现货」。

## 4. A 股资金面数据口径
- 港股通持股(东财 RPT_MUTUAL_STOCK_HOLDRANKS):MUTUAL_TYPE 002 与 004 返回同一份数据,**不能相加**(曾误报 9.73/11.76 万亿港元,正确约 5.88 万亿)。
- 北向日度净买入 2024-08-16 起停披露,只有季度快照,采集器逐期并入存档;南向是内地资金,不是外资。证金/汇金资管「持股只数」骤降是掉出十大流通股东不再披露,不是撤退。
