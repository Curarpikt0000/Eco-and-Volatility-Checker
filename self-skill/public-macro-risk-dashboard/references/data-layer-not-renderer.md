# 「点开没区别」/「图上没标 X」——都是数据层问题，不是渲染问题

Realized 2026-08-23。同一天被 Chao 提了两次，根因同构，所以合并成一页。

两类报障听起来像 UI 问题，实际都在数据层，而且**都不会报错**：

| 用户说 | 表面 | 真因 |
|---|---|---|
| 「点开第二层跟默认值没任何区别」 | 展开层没内容 | 数据只有**一个**文本字段，前端两层复用同一个 |
| 「这个图上还是没标是 C 还是 House」 | 少个标注 | 源文件**有这一列**，聚合时被静默丢掉 |

共同点：**总量守恒、校验全过、零报错**，只有人眼读图才发现不对。

---

## 一、两层展开必须两层内容

### 定位方法：先量化字段本身，别急着看渲染代码

```python
lens = [len(x.get('comments') or '') for x in rows]
lens.sort()
print(f"中位 {lens[len(lens)//2]} | 最长 {lens[-1]} | >=100字 {sum(1 for x in lens if x>=100)}")
# → 中位 32 | 最长 51 | >=100字 0
```

数字一出来就定性了：**问题在采集不在渲染**。不用读一行前端代码。

### 结构化摘要的四段式（抗注水）

```
▸ 核心论点：（主要判断）
▸ 关键依据：（引用的数据/逻辑，保留原文所有具体数字）
▸ 时间与位置：（时间窗口、点位、目标价；原文没有就写「未给出具体点位」）
▸ 标的与操作：（涉及资产，买/卖/观望）
```

比自由行文更抗注水——每段都要求可回溯到原文，写不出来就暴露了。

配 `detail_status ∈ {ok, thin, none}` 三态。**thin/none 是合格产出，不是失败**：

- prompt 里把「**宁可标 thin 也不许凑字数**」写成硬约束
- 实测正常分布：110 ok / 13 thin / 1 none（thin 5-15%）
- 真实例子：某科技公司高管确实没发表过宏观观点 → 如实写「公开信息有限，仅检索到：…」，
  而不是硬编 300 字

### 新字段必须逐层透传，漏一层就前功尽弃

```
采集产物 → 每日快照 → 历史聚合函数 → 前端 payload → 渲染函数
```

本次五层里有**四层**要改（快照函数、聚合函数的两条来源路径、payload 数组扩位、rowHtml）。
任何一层没带上 `detail`，页面就退回一句话——而且**不报错**。

★ 还要**同步写进 cron prompt**，否则次日定时任务按旧模式重跑，直接把当天成果覆盖掉。
（这条差点吃亏：cron 里那段内联代码是独立的一份，改了 build 脚本不等于改了 cron。）

### payload 扩位时不要把摘要贴到错误的日期上

历史条目本来就没有深度摘要。挂载时：

```python
det = (r.get("detail") or "").strip()        # 优先用条目自带的
if not det and dp and last >= dp["date"]:    # 才考虑「今天那条」
    det = dp["d"]
# 两者都无 → 留空，绝不把今天的摘要贴到旧观点上（那是伪造）
```

## 二、静默丢维：源文件有这一列，聚合时没了

本例：CME 交割 PDF 席位行是 `FIRM / ORG / NAME` 三列，`ORG` 就是账户类型
（`C`=Customer 代客清算 / `H`=House 自营）。解析器**已经解出 `org` 字段**，
但下游聚合 `metals[metal][date][name]["i"] += n` 只按机构名合并，把整个维度抹掉了。

**为什么难发现**：丢维后数据依然完全自洽——总量守恒、断言全过、零报错。
用户连问三次「图上还是没标客户还是 House」才被翻出来。

**唯一可靠发现方式**：拿原始文件**逐列对账**——「源里有哪些列 → 我的产物保留了哪几列」。
断言检查不出这种问题，因为它检查的是数值关系，不是维度完整性。

### 拆维后的判据：分项和必须逐条等于总量

```python
if ic + ih + iu != i or sc + sh + su != s:
    bad.append(...)
```

首版实现漏了「双通道合并时同步搬运分项」，导致 **577 处 `C+H+U ≠ 总量`**。
★ **只校验总计会漏掉这个 bug**——总计对得上，是因为主字段 `i`/`s` 搬了，分项没搬。

### 无该字段的数据通道一律标未知，绝不摊派

本例 archive PDF 段有精确 C/H，Notion 增量段原始记录**根本没有 ORG 列**
→ 该段全部计入 `U`（金银约 19-22%），前端如实显示 `? xx%`。

**不要按主通道比例摊派，不要按「大概率是 C」猜。**

### 拆完之后的读数价值（这才是做它的理由）

同一榜单里两类行为差异极大：
- 某大行白银交割 **96% 是客户盘**（自营仅 1%）→ 它是**通道**，不是在表态
- 另两家接货方 **68% / 81% 是自营** → 这才是用自己的钱在囤

**只看「谁交割最多」会把通道商误当多空主力。**
全期口径还能读出结构信号：自营接货占比 > 自营发货占比 = 做市商在用自有资金净囤实物。

## 报障响应清单

用户说「这个图/这个板块看起来不对」时，按顺序排查：

1. **先量化相关字段**（长度、非空率、枚举值分布）——多数情况这一步就定性了
2. **拿原始文件逐列对账**——我的产物是不是丢了源里有的维度
3. **确认线上产物 vs 本地产物**——从 remote 重新 clone 验，别信本地文件
   （本次有一次是浏览器缓存，线上其实是好的，让用户 `Cmd+Shift+R` 即可）
4. 最后才看渲染代码
