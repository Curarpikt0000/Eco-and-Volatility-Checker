# KOL 一年期观点全量回填 — 检索规格（2026-09-29，老名册缺月补齐 110 人）

## 背景
Chao 要求「所有 KOL 至少一年回填，全部补齐，进入仓库和 DB」。
名册中过去一年缺 ≥3 个月言论的 110 人。名单每人给了 have_months（已有）与 missing_months（缺失），**只补缺失月份**，已有月份不要再找。
本批次窗口：**2025-09-29 ~ 2026-09-29**。

## 铁律（违反即整条作废，入库脚本会硬拒）

1. **绝不编造**。每条记录必须能追溯到一个**你亲自用 web_extract 打开过的真实 URL**，
   且该页面里确实有这个人的这段观点。检索不到就少写，**宁缺毋滥**，写 2 条也可以。
2. **日期必须是原文发布日期**：只认 HTML `article:published_time`、JSON-LD `datePublished`、
   页面明确标注的发布日、YouTube 视频上传日、X 帖子时间戳。
   **禁止**用搜索摘要里的模糊日期（"3 days ago"）或你检索当天的日期。拿不到确切日期 → 不要这条。
3. **观点必须是本人说的**（本人撰文 / 访谈原话 / 本人演讲 / 本人社媒），
   不是记者转述第三方，也不是同名的其他人。**同名混淆必须排除**（职业、机构要对得上）。
4. **只收窗口内**（2025-09-29 ~ 2026-09-29）。越界会被自动拒收。
5. **专补空月**：清单里给了每人的 `have_months`（已有月份）和 `missing_months`（缺失月份），
   **优先找缺失月份**的言论，目标是一年里尽量每个月都有至少 1 条。已有月份不必再找。
6. **不是简介**：只收有判断/预测/方向性内容的言论（对利率、美元、黄金、股市、经济、地缘、政策的看法），
   不收人物简介、机构介绍、履历页面。
7. 已故的人 / 非公开发言者（例如只发官方声明的央行行长）：只收其本人公开讲话、官方发言稿，
   找不到就返回空列表并说明原因，不要硬凑。

## 输出格式
每人一个文件：`scratch/kol_bf_gap110/out/<id>.json`（id 用清单里的 id，**不要改**）

```json
[
  {
    "date": "2026-03-14",
    "direction": "看涨",
    "comments": "一句话概括他的核心观点（中文，60-120 字）",
    "targets": "金价 3500 美元/盎司（原文有明确目标价才写，没有留空字符串）",
    "source": "https://真实可访问的原文URL",
    "detail": "200-400 字的结构化详情：具体论据、提到的数字、时间判断。中文。",
    "detail_status": "ok"
  }
]
```
- `direction`：只用「看涨」「看跌」「中性」三选一（针对他谈论的主要标的/经济）
- `targets`：没有就 `""`，**不要自己推算**
- `detail_status`：拿到正文填 `"ok"`，只拿到标题/摘要填 `"partial"`
- 一个人一条都找不到 → 写 `[]`（空列表），并在回报里说明检索了哪些源

## 数量目标
每人 **8-15 条**，尽量覆盖 missing_months。真实性优先于数量。

## 检索建议
- 先用 search_terms 里的人名 + 机构名 + 月份/年份 web_search
- 本人网站 / 博客 / Substack / newsletter 存档（常带精确日期）
- YouTube 频道视频（上传日期精确）、播客节目页
- Reuters / Bloomberg / CNBC / Kitco / FT / WSJ / 财新 等引用其原话的报道
- 访谈节目（Real Vision / Kitco / Palisades / Macro Voices 等）
- 中文人物（如潘功胜）：人民银行官网讲话稿、新华社/财新报道原话

## 完成后回报（每人一行）
- id | 写入条数 | 日期范围 | 覆盖的月份数 | 主要来源域名 | 同名/找不到原因（如有）

## 搜索预算（硬约束，2026-10-02 加）
运行环境对**整轮对话**的 web_search 总数有硬上限（50 次），撞顶会被强制终止，已落盘之外的全部成果丢失。
- **每个人最多 20 次 web_search**。用完就按已找到的落盘并换下一个人，不要为凑月份死磕。
- 同名干扰多的人，先用 display 里的机构/头衔限定搜索词，一次搜不准就换 web_extract 直接打开其本人站点/Substack/YouTube，别反复换词重搜。
- **拿到第一批可核实的条目就先 write_file 落盘**，再继续补缺月（落盘可覆盖更新）。
- 搜索次数以工具调用计，不要依赖记忆；接近 40 次总数时立即落盘并写回报。
